# デバッグ方法

VSCodeでブレークポイントを置いてデバッグする方法。

Ubuntu 26.04.1 LTS, Perl v5.40.1、Remote SSH環境で確認。

## デバッグ環境のインストール

以下を流すと必要なものが入る。

```bash
sudo apt install build-essential libanyevent-perl libclass-refresh-perl libcompiler-lexer-perl \
libdata-dump-perl libio-aio-perl libjson-perl libmoose-perl libpadwalker-perl \
libscalar-list-utils-perl libcoro-perl

sudo cpan Perl::LanguageServer
code --install-extension richterger.perl
```

## CGI本体をデバッグする

`.vscode/launch.json`の「lyndbaum.cgi」で`lyndbaum.cgi`を起動する。適当にブレークポイントを置いてから起動する。

1回の起動で1リクエストだけ動いて終わる。ブラウザーやcurlからは開けず、画面に出るはずのHTMLはデバッグコンソールに出る。

開くURLなどは、`launch.json`の`env`を書き換えて指定する。

| 環境変数                                   | 指定するもの                                                                 |
| ------------------------------------------ | ---------------------------------------------------------------------------- |
| `PATH_INFO`、`QUERY_STRING`、`REQUEST_URI` | 開くパス、`?`より後ろ、その両方をつないだもの（`/lyndbaum.cgi/パス?クエリ`） |
| `HTTP_COOKIE`                              | ログインした状態で動かすときのCookie（ブラウザーの開発者ツールから写す）     |

POSTを動かすときは、送る内容をファイルに書き、`env`と`args`を次のように指定する。

```json
"args": ["<", "${workspaceFolder}/__cache/post.txt"],
"env": {
  "REQUEST_METHOD": "POST",
  "CONTENT_TYPE": "application/x-www-form-urlencoded",
  "CONTENT_LENGTH": "ファイルのバイト数"
}
```

上の例は書き換える部分だけを示している。`env`のほかの指定は残しておく。

## ツールをデバッグする

`t/tools/bench.pl`などをデバッグする際は「Perl Debug」の「program」や「args」を適当に書き換え、ブレークを設定した上でデバッガを起動するとデバッグできる。
