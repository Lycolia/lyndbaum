# 開発環境の作り方

手元でLyndbaumを動かし、テストを流してpushできるようにするまでの手順。

## 要るもの

| もの          | 使うところ                                                                    |
| ------------- | ----------------------------------------------------------------------------- |
| Perl          | 本体とテスト。動作環境は[README](../README.md#動作環境)のとおり               |
| nginx         | 画面を開いて動かすとき                                                        |
| FCGI          | 画面を開いて動かすとき（`lyndbaum.fcgi`）                                     |
| Image::Magick | テスト（`t/operations_blog.t`の画像と動画のサムネイル）。無いとテストが落ちる |
| Node.js       | pushの前の、JavaScriptの構文チェック（`node --check`）                        |
| Git           | push前のフック（`.git-hook/pre-push`）                                        |

ほかのモジュールは、使う機能に合わせて[README](../README.md#動作環境)の表から入れる。

Debian系なら、たとえば次で入る。

```bash
sudo apt install perl libimage-magick-perl nginx libfcgi-perl
```

Node.jsはバージョンを問わない（`node --check`が使えればよい）。

## 取ってきて設定する

```bash
git clone <リポジトリのURL> lyndbaum
cd lyndbaum
git config core.hooksPath .git-hook
```

- 設定ファイルは無くても動く。既定値はプログラムにある。
- 開発モードなど、値を変えたいときは`lyndbaum.user.cgi.sample`を`lyndbaum.user.cgi`としてコピーして直す。Gitの管理外。
- `core.hooksPath`はクローンごとの設定なので、クローンするたびに設定する。

## 動かす

nginxと`lyndbaum.fcgi`で動かす。設定の例は[config-example](config-example/)にある。

- `nginx.conf`：nginxの設定。`server_name`、証明書、`root`、`fastcgi_pass`のパスを手元に合わせる
- `lyndbaum.service`：`lyndbaum.fcgi`を動かすsystemdの設定。`WorkingDirectory`、`ExecStart`のパスを手元に合わせる

`lyndbaum.service`のユーザー（`www-data`）で`__cache/`、`data/`、`pub/`に書き込めるようにしておく。

設定したURLを開き、ID、パスワードを適当に入力してログインする。その後、自分自身をユーザーとして追加する。

ブレークポイントを置いてデバッグするときは[デバッグ方法](デバッグ方法.md)を参照。

## テスト

```bash
prove -lr -j"$(nproc)" t
```

テストは一時ディレクトリにブログを作り、設定はプログラムの既定値を使う。手元の`lyndbaum.user.cgi`や`data/`には左右されず、書き換えもしない。

テストのファイルごとに別の一時ディレクトリを使うので、`-j`で並べて動かせる。並べたときは、いちばん時間のかかるファイルで全体の時間が決まるので、時間のかかるテスト（操作の中身、画面のエラー）は`t/operations_*.t`、`t/screens_*.t`に分けてある。1つのファイルを流すときは`prove -l t/operations_user.t`のようにする。

## pushの前のチェック

`core.hooksPath`を設定すると、`git push`の前に`.git-hook/pre-push`が次を順に行う。どれかで止まると「=== プッシュに失敗しました ===」と理由を出して、pushしない。

| 順番 | チェック                                                                         | 止まったときの終了コード |
| ---- | -------------------------------------------------------------------------------- | ------------------------ |
| 1    | コミットされていない差分が無いこと（テストを、pushするコミットの中身で流すため） | 2                        |
| 2    | Gitで管理している`.pm` `.pl` `.cgi` `.fcgi` `.t`をすべて`perl -c`でチェック      | 4                        |
| 3    | Gitで管理している`.js`をすべて`node --check`でチェック                           | 4                        |
| 4    | `prove -lr -j"$(nproc)" t`                                                       | 3                        |

- 2、3、4は、それぞれの中でファイルをCPUのコアの数だけ並べて動かす（2、3、4は順に行う）。
- 2と3のエラーは、すべてのファイルの分をまとめて出す。
- `lib/Satsuki/Base_2.pm`のような分割ファイル（`lib/X_N.pm`）は単体では読めないので、本体（`lib/X.pm`）を先に読んでからチェックする。
- `node`がPATHに無いと3で止まる。nvmなどで入れたNode.jsは、エディターからpushするときにPATHに無いことがあるので、そのときはターミナルからpushする。
- フックを飛ばしたいときは`git push --no-verify`。

## エディター

VSCodeを使うなら、`.vscode/extensions.json`の拡張機能（ESLint、Prettier、Perl）を入れる。整形はPrettierの拡張機能に入っているPrettierで行い、設定は`.prettierrc`にある。
