# 旧システムの出力との意図的な差分

全記事の出力を旧システム（adiary）の出力と比べ、差分が無いことを目標にしている（CLAUDE.mdの「互換性」）。
ここには、意図して変えたところを理由とともに記録する。比べるときは、空白や属性の順序を正規化する。

## 記事の本文

| 項目                               | 旧システム                                                                               | 新しいシステム                                                                      | 理由                                                                                                                                        |
| ---------------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 見出しと目次のリンクのエンコード   | `href="/0575#%e8%a6%8b…"`（リンク先をパーセントエンコード）                                | `href="/0575#見出し"`（記事のURLは`Lyndbaum::URL->article`と同じ形。IDはエンコードしない） | ブラウザーではどちらも同じ見出しへ行く。旧システムと同じく記事のURLを付けるので、一覧に本文を並べても、その記事の見出しへ行く                |
| 脚注のリンク                       | `href="#fn-1"`、`href="#fnref-1"`                                                          | `href="/0575#fn-1"`、`href="/0575#fnref-1"`                                           | 一覧に本文を並べると、脚注のIDが記事どうしで重なり、ほかの記事の脚注へ飛ぶため（作者の判断）                                                 |
| YouTubeの埋め込み                 | `<module name="youtube" vid="…">`（テンプレートで展開する中間表現）                      | `<iframe class="youtube-player" …>`を直接出力する                                  | テンプレートでの展開をやめ、パーサーの出力をそのまま表示できるようにするため                                                                |
| 添付ファイル（画像、動画）のパス   | `/pub/lycolia/image/…`                                                                   | `/pub/attachments/…`（設定の`attachment_path`）                                    | 画像以外のファイルも置くため。記事の原文に書かれた旧パスは移行で書き換える。旧URLからの転送はWebサーバーの設定で行う                        |
| 添付ファイルのフォルダの名前       | `adiary/年/月/`                                                                          | `posts/年/月/`                                                                      | adiaryではなくなるため（作者の判断）。旧データの取り込みで、記法（`[image:S:adiary/…]`）、URL、アイキャッチを書き換える。`@system/`はそのまま |
| バナー、キャプション付きの画像     | `<p><div class="notice_banner">…</div></p>`、`<p><figure>…</figure></p>`                 | `<p>`で囲まない                                                                    | `<p>`の中に`<div>`や`<figure>`は置けず、HTMLとして不正なため                                                                           |
| 続きを読むの印                     | `<!--%SeeMore%-->`                                                                       | `<!--more-->`                                                                       | 新しいシステムで決めた印。表示するときにこの印で分ける                                                                                      |
| 空行を挟んだリストの項目           | 項目ごとに決める（直後に空行がある項目、中に空行がある項目だけ`<p>`で囲む）            | CommonMarkと同じくリスト単位で決める（空行が1か所でもあれば全項目を`<p>`で囲む） | GitHubやVS Codeのプレビューと同じ表示にするため。Prettierで整形し直した記事は、空行の位置がそろう                                       |
| 番号付きリストの開始番号           | 常に1から                                                                                | `3.`から始まれば`<ol start="3">`                                                  | 書いた番号のとおりに表示するため（仕様書のとおり）                                                                                          |
| 対応しない記法                     | 旧パーサーの解釈による                                                                   | 普通の文章として表示する                                                            | `docs/markdown-syntax.md`の「対応しない記法」。いずれも使用数は0                                                                          |
| 代替テキストを省いた画像の`title` | `title="image:S"`                                                                        | `title=""`                                                                          | 旧システムの不具合                                                                                                                          |
| 画像の拡大表示の属性               | `data-fancybox="k記事ID"`                                                                | `data-lythumb="k記事ID"`                                                            | 画像の拡大表示をFancyboxから自作のLythumbに替えたため。記事の原文の生HTMLに書いた`data-fancybox`は、旧データの取り込みで書き換える              |
| ファイル名と同じ代替テキスト       | ファイル名が英数字と一部の記号だけなら空、それ以外はファイル名を`alt`と`title`に出す | 旧データの取り込みで原文から落とし、空にする                                        | 代替テキストとして意味が無く、検索で当たらないようにするため                                                                                |
| 添付ファイルのファイル名           | エンコードしない、または小文字の`%xx`                                                   | 空白などをパーセントエンコード（大文字の`%XX`）                                    | 空白を含むURLはHTMLとして不正なため                                                                                                         |
| 動画の代替表示                     | `(Browser not support video tag)`と、パスを文字にしたリンク                             | ファイル名を文字にしたリンク                                                        | 代替表示の文言を簡単にした                                                                                                                  |
| 記事の説明（一覧に出す要約）       | 本文の文章の先頭64文字。`<`などを文字参照（`&lt;`）のまま数えて保存していた             | 文字に戻してから数える。保存と再構築のときに作る                                    | 旧システムの不具合。旧データの769件のうち28件が、この違いで変わる                                                                           |
| コードの色付けの言語の別名（`pub/assets/js/article.js`） | `sh`→`bash`、`bat`と`cmd`→`batch`、`pwsh`→`powershell` | 左に加えて、`ps1`→`powershell`、`c#`→`csharp`（大文字と小文字は区別しない） | 旧システムでは、この2つの言語のコードに色が付いていなかったため |

## 旧システムの不具合を直したもの

全記事の比較で見つかった、旧システムの出力の誤り。新しいシステムでは直すので、出力が変わる。

| 項目                                              | 旧システム                                                                             | 新しいシステム                     | 該当する記事                            |
| ------------------------------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------- | --------------------------------------- |
| コードスパンの中の`\`                            | エスケープとして処理し、`\`が消える（`%USERPROFILE%\.gnupg` → `%USERPROFILE%.gnupg`） | そのまま表示する（仕様書のとおり） | 15, 21, 40, 95, 160, 471, 581, 654, 658 |
| 表のセルの中の`\|`                               | セルの区切りとして扱う                                                                 | 縦棒として表示する（GFMと同じ）   | 155                                     |
| 表のセルのコードスパンの中の`\|`                 | セルの区切りとして扱い、内容の一部が消える                                             | 縦棒として表示する（GFMと同じ）   | 260                                     |
| リンクの文字の中の角括弧（`[a [b] c](URL)`）      | リンクにならない                                                                       | リンクにする                       | 179, 264                                |
| リンク先の入れ子の括弧（`(…(…))`）                | 最初の`)`で切れる                                                                    | 対応する`)`まで                  | 203                                     |
| `:`を含む画像の代替テキスト                      | `title`が最後の`:`より後ろだけになる                                                | 代替テキストのとおり               | 189                                     |
| 許可しない生のタグ（`<M>`、`<x86 Panther Lake>`） | 小文字のタグとして出力する                                                             | 文字として表示する                 | 546, 773                                |
| リストの項目の先頭の`>`                          | 項目によって引用になったりならなかったりする                                           | 引用にする                         | 678                                     |

## 比べ方

```sh
perl t/tools/corpus-diff.pl data lycolia            # 一致した記事の数と、違いのあった記事の一覧
perl t/tools/corpus-diff.pl --id=575 data lycolia   # 1記事の差分
perl t/tools/corpus-diff.pl --diff data lycolia     # 違いのあった記事の差分
```

旧システムの出力（記事データの`text`欄）は、記事を最後に保存したときのパーサーで作られている。そのため、記事によって旧パーサーの版が違い、同じ書き方でも出力が違うことがある。
