# 動画のサムネイル

記事のページでは、動画とYouTubeを最初からプレーヤーで出さず、サムネイルの画像だけを出す。サムネイルを押すと、Lythumb-viewer（`pub/assets/js/lythumb.min.js`）で開いて再生する。

ページを開いただけでは、プレーヤー（`<video>`、YouTubeの`<iframe>`）を読み込まないようにするのが目的。

## 記事のページでの出し方

どちらも`data-lythumb`の付いたリンクの中に、サムネイルの`<img>`を入れる。Lythumb-viewerは、リンク先のURLから動画やYouTubeだと判断して再生する。

```html
<a href="pub/attachments/posts/2026/clip.mp4" data-lythumb="k%k" class="video-thumb">
	<img alt="" width="480" height="270" src="pub/attachments/posts/2026/.thumbnail/clip.mp4.poster.avif">
</a>
<a href="https://www.youtube.com/watch?v=動画ID" data-lythumb="k%k" class="video-thumb youtube">
	<img alt="" width="480" height="360" src="https://i.ytimg.com/vi/動画ID/hqdefault.jpg">
</a>
```

- `data-lythumb`のグループ名は、画像と同じく記事ごとの名前にする。記事の中の画像と動画は、1つのギャラリーとして前後にめくれる
- サムネイルの上には、CSS（`base.css`の`a.video-thumb`）で再生の印を重ねる。画像のファイルは使わない
- JSが動かないときは、ただのリンクになる。動画ファイルはブラウザーがそのまま再生し、YouTubeはYouTubeのページが開く

### 動画ファイル

- 対象は`[file:…]`、`[video:…]`、`[&URL]`で出す動画（`mp4`、`m4v`、`webm`、`ogv`）
- 記法を変換するときに、そのブログの中の動画で、サムネイル（下の「サムネイルの置き場所」）があればサムネイルを出す（`Tag_audio.pm`）。無ければ、今までどおり`<video controls preload="none">`を出す
- 画像ビューアーを使わない設定（パーサーの`image_attr`が空）のときも、`<video>`を出す
- `w`、`h`の大きさの指定は、サムネイルの`<img>`の大きさにする。指定が無ければ、長い辺を`<video>`やYouTubeの幅と同じ480pxに収める（縦長の動画は高さ480px。サムネイルのファイルが小さければ、ファイルの大きさ）。本文の幅より広ければCSSで縮める
- サムネイルを作ったり消したりしたときは、その動画を使っている記事を作り直す（`rebuild_arts_using_files`）

### YouTube

- 対象は`[youtube:動画ID]`と、`[&https://www.youtube.com/watch?v=…]`（どちらも`Tag_url_filter.pm`が`<module name="youtube-thumb">`にし、`info/allow_tags_article.txt`のモジュールでHTMLにする）
- 画像ビューアーを使わない設定（パーサーの`image_attr`が空）のときは、今までどおりプレーヤー（`<module name="youtube">`）を埋め込む。本文に直接書いた`<module name="youtube">`もプレーヤーのまま
- サムネイルは`https://i.ytimg.com/vi/動画ID/hqdefault.jpg`を直接読む。サーバーには保存しない
  - `hqdefault.jpg`はどの動画にもある（`maxresdefault.jpg`は無い動画がある）。4:3で上下に黒い帯が入るので、CSSで16:9に切り取って出す
- `small`、`large`の大きさの指定は、サムネイルの幅にする（320、640。指定が無ければ480）
- 再生開始位置（`t`、`start`）は、リンクのURLに残す。Lythumb-viewerが引き継ぐ

## サムネイルの置き場所

メディアの中で、動画と同じフォルダの`.thumbnail/`に置く。

| ファイル | 中身 |
|---|---|
| `.thumbnail/動画名.poster.avif` | 記事に出すサムネイル。長い辺を最大960px（記事での既定の表示480pxの2倍。高解像度の画面でもぼやけないように）にする |
| `.thumbnail/動画名.avif` | メディアの一覧に出すサムネイル。画像と同じ大きさ（「編集画面の設定」のサムネイルの大きさ） |

- 形式は画像のサムネイルと同じく、ImageMagickでAVIFを書けるならAVIF、書けなければJPEG（`.poster.jpg`、`.jpg`）にする。前に作ったJPEGが残っていることもあるので、使うときはAVIFを先に探す（記事は`Tag_audio.pm`の`video_thumbnail`、サーバーは`poster_file`）
- `動画名`は拡張子まで含める（`clip.mp4.poster.avif`）。画像のサムネイル（`.thumbnail/ファイル名.avif`か`.jpg`。[画像のメタ情報とサムネイル](画像のメタ情報とサムネイル.md)）と同じ付け方
- サムネイルを作るまでは、`.thumbnail/動画名.jpg`に動画のアイコンが入っている。サムネイルを作ると、動画の1コマに置き換わる（アイコンは消す）
- サムネイルを作ると、ほかの形式の古いサムネイルは消す
- メディアでファイルを移動、名前を変更、削除したときは、画像のサムネイルと同じく記事用のサムネイルも一緒に移動、名前を変更、削除する（どの形式も）

記事用のサムネイルの大きさ（960px）は、ページの読み込みの量と、Lythumb-viewerで開いたときの見え方の間を取っている。

- Lythumb-viewerは、記事のサムネイルを動画の`poster`にも使う。再生が始まるまで、最大1600pxに引き伸ばして出す。小さいほど粗くなる（4.16では1280pxにしていた）
- 記事の中では480pxで出すので、それより大きいほど読み込みの無駄が増える
- 480pxにすると、記事の中では画像のサムネイルやYouTubeのサムネイル（`hqdefault.jpg`、480×360）と同じ1倍になる。その代わり、ビューアーで粗くなり、`w`、`h`で480より大きく指定した動画もぼやける
- 形式は画像のサムネイルと同じ（AVIFかJPEG）にし、サーバー（ImageMagick）で書き出す。ブラウザーの`canvas`はAVIFを書き出せず、WebPも書き出せないブラウザーがあるので、ブラウザーからはPNGで送る
- Lythumb-viewerは、サムネイルの`<img>`の`currentSrc`を`poster`に使うので、AVIFでもよい

## サムネイルの作り方

サーバーではコマンド（ffmpegなど）を動かさないので、動画の1コマはサーバーで切り出せない。管理画面で、編集者のブラウザーが1コマを切り出してサーバーに送り、サーバーがサムネイルにする。

1. ブラウザーで`<video>`に動画を読み込み、1秒の位置（1秒より短い動画は長さの半分）に送る
2. そのコマを`<canvas>`に描き、長い辺を最大960pxにしたPNGにする
3. PNGを`media/upload_video_thumbnail`で送る
4. サーバーは、送られたPNGから、記事用とアルバム用のサムネイルを作る。どちらも画像のサムネイルと同じ処理（`make_jpeg_thumbnail`）で、形式（`thumbnail_ext`）と品質（AVIFは`album_avif_quality`、初期値65。JPEGは`album_jpeg_quality`、初期値80）も同じ。AVIFを書けなければJPEGで作る

ブラウザーからPNGで送るのは、圧縮を1回だけにするため。ブラウザーでJPEGにすると、サーバーでもう一度圧縮したときに、2回圧縮することになる。

処理は`admin.js`の`$$.make_video_thumbnail`（1つ）と`$$.make_video_thumbnails`（まとめて）。作るのは次のとき。

- メディアで動画をアップロードしたとき（アップロードが終わった後に、続けて作る）。アップロードの応答の`video=名前`の行で、アップロードした動画を受け取る
- 記事の編集画面で動画をアップロードしたとき（`etc/ajax_upload`の応答の`isVideo`）。作り終わる前に記事を保存しても、作り終わったときに記事を作り直す
- メディアで動画を選び、「その他の操作」の「動画のサムネイル作成」を選んだとき。前からある動画や、作り直したいときに使う
- アップデート処理の後（下の「アップデート処理」）

ブラウザーが再生できない形式の動画は、作れない。その動画は、記事に今までどおり`<video>`で出す。

### 受け取る側（`media/upload_video_thumbnail`）

- 編集者だけが使える。フォルダの名前は、画像のアップロードと同じく確かめる（`image_folder_to_dir`）
- 動画のファイルがそのフォルダにあり、拡張子が動画のもの（`mp4`、`m4v`、`webm`、`ogv`）であることを確かめる
- 送られたデータがPNGで、長い辺が960px以下であることを確かめる（`ImageFormat::get_size`）。違うときや、記事用かアルバム用のサムネイルを作れなかったときは、記事用のサムネイルを置き換えない
- 保存する名前はサーバーで決める（上の表）。送られたファイル名は使わない

### メディアの「サムネイルの作り直し」

サーバーで画像のサムネイルを作り直すとき（`media/remake_thumbnail`）、記事用のサムネイルのある動画は、アルバム用のサムネイルをアイコンに戻さない。

## アップデート処理

アップデート処理（サーバー）では動画の1コマを切り出せないので、記事の作り直しまでを行い、サムネイルはその後にブラウザーで作る。

- v4.16のアップデート処理で、YouTubeのある記事を作り直す
- アップデート処理が終わると、アップデートの画面（`system/update`）に戻り、メディアの中の次の動画（ゴミ箱を除く）のサムネイルを、続けてブラウザーで作る（`load_videos_need_thumbnail`）。作った動画を使う記事は、そのたびに作り直す
  - 記事用のサムネイル（`.poster.avif`か`.poster.jpg`）の無い動画
  - 記事用のサムネイルの長い辺が、今の上限（960px）より大きい動画。4.18より前は1280pxで作っていたため
  - 記事用のサムネイルが、v4.19のアップデート処理より前に作ったものの動画（ファイルの更新日時で見る）。4.19より前は、ブラウザーが品質0.85のJPEGで作っていたため。v4.19のアップデート処理で、その時刻をシステムの設定（`video_poster_time`）に残す
  - AVIFを書けるサーバーで、記事用のサムネイルがJPEGの動画。4.25より前はJPEGで作っていたため。JPEGからAVIFに変換すると圧縮が2回になるので、動画から作り直す
- 途中で画面を閉じたときや、作れなかった動画があるときは、アップデートの画面の「サムネイルを作る」で続きを作れる。上の動画があれば、この欄が出る
