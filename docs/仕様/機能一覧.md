# 機能一覧

adiaryの機能を、コードから洗い出した一覧。詳しい仕様は、必要になったものから`docs/仕様/`の下に書く。

- 調査の時点：2026-10-24（`ed230884`）
- 印

  - 【要確認】動くかどうか、今も要るかどうかを確かめていないもの
  - 【不具合】動かないことが分かっているもの

## 権限の呼び方

| 呼び方         | コードでの判定 | 内容                                                           |
| -------------- | -------------- | -------------------------------------------------------------- |
| 誰でも         | なし           | ログインしていない人も含む                                     |
| ログイン中     | `Auth.ok`      | ログインしている人                                             |
| 編集者         | `v.allow_edit` | そのブログの管理者か、編集者に指定された人（ブログの権限設定） |
| ブログ管理者   | `v.blog_admin` | そのブログの管理者。システム管理者も含む                       |
| システム管理者 | `Auth.isadmin` | ユーザーの管理画面で管理者にした人                             |

ブログの管理者、編集者、コメントできる人を指定するユーザーIDの一覧は、「`,`」区切りで書く。ユーザーIDが一覧の1項目と完全に一致した人だけを認める（`users_check`）。一覧が「`*`」なら全ユーザーを認める。

## 1. 画面

画面は`skel/`の下のテンプレート。URLは`lyndbaum.cgi?ディレクトリ/ファイル名`（`skel/set/detail.html`なら`?set/detail`）。

### 権限の確かめ方

- 管理画面の多くは、画面の中のメニュー（`_sub/menu_tree`。タブで出す）を出すときに、そのディレクトリの`_items.html`を呼び、そこで権限を確かめる（足りなければ403のページに切り替える）。メニューを出さない画面は、画面の中で自分で確かめる。
- `skel/set/`は`_dir_tree.html`で確かめる（ブログ管理者）。
- 2026-10-24の時点で、管理画面はすべて、どちらかの方法で権限を確かめている。

### 公開画面

| URL       | 画面                                    | 使える人 | 備考                                                                               |
| --------- | --------------------------------------- | -------- | ---------------------------------------------------------------------------------- |
| （なし）  | トップ（`_top`）、記事の一覧（`_main`） | 誰でも   | ブログがまだ無ければ`_top`、あれば`_main`。FrontPageの設定があれば記事の画面になる |
| 記事のURL | 記事（`_article`）                      | 誰でも   | コメントの投稿もここ。記事の情報（`_sub/art_info`）に、コメント欄と参照元へ飛ぶリンクを出す。脚注（`[^id]`）と注釈（`((注釈))`）の番号は、マウスを乗せるか（タッチの端末では押すと）、注の中身をその場にポップアップで出す（`adiary.js`）。NSFWの記事は、本文をぼかして年齢確認を出す（下の「NSFWの記事」） |

#### NSFWの記事

記事の詳細設定の「NSFW」、または編集画面の設定の「ブログ全体をNSFWにする」（`nsfw_force`。すべての記事の`nsfw`を1として読む）で、記事を成人向けにする。

- 年齢確認（`_sub/nsfw_gate`）を重ね、その下をぼかす。ぼかすところは次のとおり
  - 記事のページと一覧：NSFWの記事ごとに、本文（`body-main`の中）。題名、記事の情報、コメント、ページ送りなどはぼかさない
  - ブログ全体がNSFWのとき：どのページも画面全体。年齢確認を画面全体に重ね、その下をぼかす（`backdrop-filter`。中身には`filter`をかけない）。記事ごとには出さない
- 年齢確認の枠は、テーマの色によらず白地に黒の文字で出し、上からの位置を決めて出す（中身の長さで動かない）
- 「18歳以上なので表示する」を押すと、その年齢確認を重ねたところだけぼかしを外す。JavaScriptが無効のときは本文を見られない
- 「今後確認しない」も付けて押すと、ブラウザーのlocalStorage（`adiary-nsfw-ok`）に覚え、このページとこれから開くページのNSFWの記事をぼかさない
- ブログ全体の確認には「今後確認しない」を出さず、ブラウザーを閉じるまでsessionStorage（`adiary-nsfw-ok`）に覚える。ブラウザーが前のセッションを戻す設定だと、閉じても残る
- 覚えているときは、ぼかすところの上に「確認を元に戻す」を出す。押すと忘れ（localStorageとsessionStorageの両方）、このページのNSFWをまたぼかす
- NSFWの記事があるページと、ブログ全体がNSFWのときは、`<meta name="rating" content="adult">`を出す（`_frame.html`）
- SNSのカード（OGP）には記事のメイン画像を出さず、ブログの既定の画像にする
- RSSには本文とコメントとアイキャッチを出さず、年齢確認があるという文だけを出す。`nsfw_force`を変えたら、RSSを書き出し直す

#### 管理バー

ログイン中は、公開画面の上に管理バー（`_sub/admin_bar`）を貼り付ける。テーマによらず`_frame.html`が出し、デザインの編集では出さない。

- 中身は「ようこそ○○さん」（管理画面へのリンク）、新着のコメントの印（あれば。押すとコメント一覧）、書く（編集できる人）、ログアウト。項目は右に寄せる
- アップデートが必要なときは、システム管理者にだけ「アップデート」の印を出す（押すとアップデート処理の画面）。形と色は新着の印と同じ。管理画面では、本文の上に同じ知らせを出す（`_sub/require_update_notice`）
- ログイン中の画面は`Cache-Control: private, no-store`にする（管理バーや管理者だけの知らせが入るため）
- 記事の（編集）は、管理バーには出さず、記事の情報（`_sub/art_info`）に出す
- WordPressの管理バーと同じく、1行に収めて高さを決め打ちにし（`--admin-bar-h`）、その分だけページを下げる（`html`の`margin-top`）。アンカーで飛んだ先も、バーの裏に入らないよう下げる（`scroll-padding-top`）
- 新着の印の色は、管理画面のナビとダッシュボードの新着の印（`admin-new-badge`）にそろえる

#### JavaScript

- ログインしていない人の公開画面は、`pub/assets/js/adiary.js`だけで動く。jQueryとasys.js（`asys.min.js`）は読まない
- システムモード（デザイン編集など）とログイン中は、`asys.min.js`と`admin.js`も読む（`_frame.html`）。記事のページのコメントの管理（確認のダイアログなど）に使う
  - このとき`window.adiary`はasys.js（`$$`）になる。テンプレートなどから`adiary.〜`で呼ぶ`adiary.js`の関数（`css_init`、`init_top_search`、`word_highlight`など）は、`admin.js`が`$$`からも呼べるようにする
  - `<script-defer>`の実行と`js-switch`は、asys.jsを読んだページではasys.jsが行い、読まないページでは`adiary.js`が行う（`js-switch`はチェックボックスだけ）
- テーマとプラグインのJavaScript（natureのテーマ、時計、メモ、360度写真）もjQueryを使わない

#### パスワード

- パスワードは8文字以上（`Auth.pass_min`）。数字だけのものは使えない。bcryptが72バイトより後を無視するので、72バイトを超えるものは断る
- パスワードはbcrypt（`$2b$`、コスト12）で保存する（`lib/Satsuki/Auth_3.pm`の`hash_pass`）。OSの`crypt()`を使うので、`$2b$`に対応していないサーバーではパスワードを保存できない

## 2. 操作（POSTとAjax）

### 振り分け

POSTの`action`の値で、呼ぶ処理を決める（`lib/SatsukiApp/adiary.pm`の`main`）。GETでは操作は動かない。

| `action`の形        | 呼ぶ処理                                             | 権限                                                            |
| ------------------- | ---------------------------------------------------- | --------------------------------------------------------------- |
| `_ajax_名前`        | 同じ名前のメソッド（`do_ajax_function`）。結果はJSON | `_ajax_login`以外はログイン中。そのうえでメソッドの中で確かめる |
| `ディレクトリ/名前` | `skel/ディレクトリ/_action/名前.html`                | 操作の中で確かめる（下の表）                                    |

- 操作の中の権限の確かめ方は2通りある。操作の冒頭（`ifbreak(!v.allow_edit)`など）で確かめるものと、呼び出し先の関数の中（`Operation not permitted`を返す）で確かめるもの。
- 2026-10-24の時点で、ログインを前提にした操作はすべて、どちらかの方法で権限を確かめている。

### CSRFの対策

- 確認キー（CSRFトークン）は使っていない。原作者がVer3.50で、Cookieの`SameSite`で足りるとして除去した（https://adiary.adiary.jp/0422）。4.09で、その消し残し（いくつかのフォームの`csrf_check_key`の欄と、それを送るJavaScript）を消した。
- ログインのCookieに`SameSite=Lax`を付けている（`lib/Satsuki/Base_2.pm`の`put_cookie`。`CookieSameSite`で変えられる）。ほかのサイトからのPOSTにはCookieが送られないので、ログイン中の操作をさせられることはない。
- `SameSite=Lax`でも、ほかのサイトのリンクから開くGETにはCookieが送られる。そのため、GETでは状態を変えないことが前提になる。操作はPOSTでしか動かない（上の「振り分け」）。`_action/`と`_sub/`のスケルトンは`_`で始まるので、URLからは開けない（`parse_skel`）。
  - 開くだけで書き込む画面は次のものだけ。どれも、ほかのサイトから開かせても、データを書き換えたり消したりはできない。
    - `?logout`：セッションを消す（ほかのサイトのリンクでログアウトさせることはできる）
    - `?login_auto`：システム管理者が1人もいないときだけ、`root*`でログインする
    - `?menu`：システムの情報の`myself`、`myself2`が無いときだけ書く
    - `?comlist`、記事のページ：ブログの編集者が開くと、新着コメントの印を消す
    - `?media/`：アルバムのフォルダが無ければ作り、フォルダの一覧（`images.json`）を今のフォルダから作り直す
    - ブログが無いときのトップ（`skel/_top.html`）：ログインしていない人が開くと、ユーザーのテーブルが無ければ作る（`userdb_init`）
  - テスト：すべての操作をGETで送っても通らないこと（`t/permission_action.t`）、すべての画面を開いても`data/`と`pub/`が変わらないこと（`t/screens_admin.t`、`t/screens_public.t`。上の書き込みは`%GET_WRITES`に理由と書く）を確かめている。
- 同じサイトの中からのPOSTは`SameSite`では防げない。そのため、記事の本文にはフォームの部品（`form`、`input`、`button`、`select`、`textarea`など）を書けないようにしている（4.09、`info/allow_tags_article.txt`）。書けると、ほかのユーザーが記事に管理画面の操作へ送るフォームを置き、システム管理者に押させることができる。

### 文字数の数え方

- フォームの値の上限（`lib/Satsuki/Base_2.pm`の`form_type_check`）と表示用の切り詰め（`lib/SatsukiApp/adiary_2.pm`の`string_clip`）は、Unicodeのコードポイントの数で数える（`Satsuki::Code::Jcode`の`jlength`、`jsubstr`）
- 見た目の1文字（書記素クラスター）では数えない。結合文字の濁点、ZWJでつないだ絵文字、国旗、肌の色の指定などは、見た目は1文字でも2文字以上と数え、途中で切ることもある
- 書記素クラスターで数えないのは、結合文字をいくらでも重ねられ、1文字の長さに上限が無いため。書記素で数えると、上限が大きさの上限にならない

### 外部のサイトとの通信

更新通知、`[&URL]`のタイトルの取得、外部画像の取り込みなどは、`Satsuki::Base::HTTP`で外部のサイトに接続する。

- httpsでは、接続先の証明書の信頼チェーンとホスト名を、サーバーのCA証明書で検証する。問題があれば接続せず、接続の失敗として扱う。検証を外す設定は無い
- URLがIPアドレスのときは、証明書にそのIPアドレスがあれば接続する。SNIは送らない
- Net::SSLeayはVer1.92以降が必要。古ければ接続せずエラーにする
- httpの接続、httpsからhttpへのリダイレクトは暗号化されないので、この検証では守れない
- 制限時間は既定で30秒。更新通知は`http_timeout`の値を使う
  - httpsは、TLSハンドシェイク、送信、受信の合計に掛かる。TCP接続とは別に数える
  - httpは、受信に掛かる。TCP接続とは別に数える。送信には掛からない
  - 時間を超えたら、途中まで受信していてもタイムアウトのエラーにする
  - ノンブロッキング通信で期限まで待つ。FastCGIのスレッドごとに独立して扱う
- ステータス200の本文が`Content-Length`より短いときは、切断のエラーにする。`Content-Length`が無い応答の途中切断は検出できない
- リダイレクトは5回まで辿る。辿った先で失敗したら、そこで打ち切る

## 3. 設定

設定は3か所に分かれている。普段は画面で変える。`lyndbaum.user.cgi`は、画面に無い項目を変えるときだけ手で書く。書いていない項目は、プログラムの既定値で動く。

| 置き場所                                                         | 変える画面                          | 内容                                                   |
| ---------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------ |
| `lyndbaum.user.cgi`（gitの管理外。無くてもよい。見本は`lyndbaum.user.cgi.sample`） | なし（ファイルを書き換える） | タグの制限、アップロードの拡張子、ログインできるIPアドレス、サーバーの環境など、画面に出さない設定 |
| `data/system_config.dat`（既定値は`info/default_config.dat`）    | `?system/setting`（システム管理者） | メンテナンスモード、キャッシュ、ログイン、アップロードの上限など、システム全体の設定 |
| `data/blog/setting.dat`（既定値は`info/default_setting.dat`）    | `?set/`など（ブログ管理者）         | ブログごとの設定                                       |

- 新しいブログの設定の既定値は、`info/default_setting.dat`。
- 起動の順番は、DB、ログイン、本体を作る（`lib/Satsuki/Base.pm`の`setup_main`）、`lyndbaum.user.cgi`を読む、時刻とパスを初期化する（`init_tm`、`init_path`）。この順番なので、ユーザー設定で`v.*`、`Auth.*`の値と、初期化で使う`Basepath`、`ModRewrite`、`ServerURL`、`ENV.TZ`を変えられる。
- 既定値は、`adiary::SetDefaultValue`（`v.*`）、`Auth::new`と`setup_main`（`Auth.*`）にある。フォームの制限は`Base_2.pm`の`set_form_options`。
- フォルダの場所、関連ファイル、`v.parsers`、`v.default_theme`、`v.rss_skeleton`、`v.words_separator`、アルバムのアイコンとフォントは、変えない項目として扱う。見本にも載せない。
- `Develop`と`__cache_dir`は、ユーザー設定を読んだ後に効く。
- `lyndbaum.user.cgi`が無く、4.27までの`lyndbaum.conf.cgi`があれば、アップデート処理で移すまでは`lyndbaum.env.cgi`と`lyndbaum.conf.cgi`で動く（[アップデート処理](アップデート処理.md)）。
- 画面に出すのは、間違えても画面から直せて、サーバーへの権限が広がらない項目だけ。次はファイルに残す。
  - `v.trust_mode`、`v.admin_trust_mode`：乗っ取られた管理者が自分で制限を外せてしまう
  - `v.album_allow_ext`、`v.album_image_ext`：`.cgi`などを許すと、管理者の権限がサーバーでのプログラムの実行に広がる
  - `v.static_export`：全ユーザーに開くスイッチ
  - `Auth.allow_ip`、`Auth.allow_host`、サーバーの環境（`Basepath`など）：間違えると画面に入れなくなる
  - `v.stop_all_plugins`：画面が壊れたときの復旧に使う
- 画面の値は、`adiary`の`apply_sys_settings`で起動時に反映する。認証とフォームの読み込みより先に行う。同じ項目がファイルにもあれば、画面で保存した値を優先する。空で保存すると、ファイルか既定の値に戻る。
- ファイルで画面の範囲の外にしている項目は、画面の欄を止めて送らない。ほかの項目は保存でき、その項目の値は変わらない。
- ブログの設定に項目を足したときは、値が空なら既定値を使うようにする（今あるブログの`setting.dat`には、その項目が無いため）。

#### プライベートモード（削除）

ブログ全体を権限のある人だけに見せるプライベートモードは、4.27で削除した。一緒に、閲覧できる人（`viewers`）、表示のパスワード（`view_pass`）、公開フォルダのファイルを推測できない名前のフォルダに置く仕組み（`pub_private_dir`）も削除した。ファイルは名前を隠すだけで保護できず、表示のパスワードは設定とCookieに平文で保存していたため。

- ブログ全体を閉じたいときは、Webサーバーの認証を使う
- 記事ごとの非公開（`enable`）は残す。非公開の記事の添付ファイルは、URLが分かれば見られる
- `v.allow_view`は、ブログを選べたか（ブログがあるか）を表す。ブログが無いときはトップと記事のURLが404になる。`!v.blog`では見ない（`v.blog.○○`を読むと、ブログが無くても空のハッシュができるため）
- アップデート処理は「[アップデート処理](アップデート処理.md)」の「プライベートモードの削除」

#### RSS

RSS 2.0で、`rss.xml`を書き出す（`generate_rss`、テンプレートは`skel/_format/rss20.html`）。記事やコメントの状態が変わったとき、ブログの設定を保存したときに書き出し直す。件数とコメントを含めるかは詳細/コメント設定で決める。

- 画像はMastodonと同じ書き方で出す
  - チャンネルの`<image>`：基本設定のサイトアイコン（`iconfile`）。無ければ既定のアイコン（`default-icon.png`）。`title`と`link`はチャンネルと同じにする。幅と高さは、アイコンの大きさが分かり、幅144・高さ400以下のときだけ書く（RSS 2.0の上限）
  - 記事の`<media:content>`（Media RSS）：アイキャッチ（`main_image`）。本文に無い画像のこともある。`type`は拡張子から、`width`と`height`は分かるときだけ書く。NSFWの記事には出さない
- `<image>`で使える形式はGIF/JPEG/PNGだけなので、サイトアイコンにはPNG・JPEG・GIFしか上げられない（`skel/set/_action/index.html`）。アイコンの幅と高さは、上げたときに設定に保存する（`iconfile_w`、`iconfile_h`）
- 決めたタグの記事だけを`rss2.xml`に書き出す「2つ目のRSS配信」は4.24で削除した。


### 3.4 サブドメインモード（削除）

`v.subdomain_mode`で、ブログを`ブログID.ドメイン`で表示する機能があったが、4.09で削除した。HTTPSのときにほかのブログへのリンクが`http://`になる、`default_blogid`が入っていると働かない、ログインのCookieを全ブログで共有するなどの問題があり、保守の手間に見合わないため。設定ファイルに`v.subdomain_mode`が残っていても無視する。

### 3.5 複数のブログ（削除）

1つのadiaryで複数のブログを持つ機能は、4.10で削除した。ブログは1つだけにする。ユーザーを複数持つ機能と、ブログの権限設定（管理者・編集者）は残す（閲覧者は4.27で削除した）。

- 削除した：ブログの一覧（`?blogs`、`?blogs_sys`、システム設定の`blogs_allow`）、任意のブログの作成（`?system/blog_create`、ほかのブログのコピー）、ブログの削除（`?mainte/blog_drop`。全記事の削除は`?mainte/blog_clear`として残した）、アルバムのブログ一覧（ブログの設定の`album_blogs`）、システム設定の`create_blog_only_admin`とデフォルトブログの選択、新しいブログの初期設定の編集（`?set/…&blogid=*`と、保存先の`data/default_setting.dat`。ファイルが残っていても読まない）
- ブログの作成：ブログがまだ無いときだけ、システム管理者が`?etc/myblog_create`から作れる
- ブログIDは持たない。テーブル名、データのフォルダ、公開フォルダは決まった名前（「5. データ」）。ユーザーIDとブログIDが同じ人をブログ管理者とみなす判定も無くし、ブログ管理者はシステム管理者と、権限設定で指定した人だけ
- URL：いつもそのブログを表示する。`/ブログID/`のURLでほかのブログを表示する振り分けは無くした（`/ブログID/…`は記事のURLとして扱う）。ブログが無いときは、ブログがまだ作られていない旨を出す
- 非公開モード：公開フォルダの名前に乱数を付け足して画像のURLを隠す仕組み（`blogpub_dir_postfix`、システム設定の`dir_postfix_len`）は削除した
- 全ブログに対する処理：システム管理の再構築・付加情報の再生成・プラグインの再インストール・カスタムCSSの作り直しと、アップデート処理は、そのブログだけを処理する
- ほかのブログへのリンクの記法（`[id:ブログID]`、`[id:ブログID:記事]`）と、エクスポートの「id記法を通常リンクに書き換え」（`id2link`）も削除した

### 転送（`redirect()`）

- テンプレートの中からでも、Perlの側（`main`の中）からでも呼べる。転送のページを出した後、`die("Break")`で処理を抜ける。
- Perlの側から呼んだときは、`Satsuki::Base`の`start_up`で`Break`を受け止め、終わりの処理（`finish()`）まで進める。
- テンプレートの中から呼んだときは、`$ROBJ->{Redirected}`の印を立て、`output_html`でページを出さない。
- 4.09より前は、Perlの側から呼ぶと302の後ろに500のエラーが付いて`finish()`が飛び、テンプレートの中から呼ぶと302の後ろにページ全体をもう一度出していた。

### Amazonの記法（削除）

- `[asin:…]`、`[isbn:…]`、`[amazon:…]`の記法（`Tag_amazon.pm`）、さつき記法でAmazonの商品のURLを商品のリンクに変える処理（`Tag_url_filter.pm`）、ブログの設定のアフィリエイトID（`asid`）を、4.09で削除した。
- 商品名は手で書く必要があり、画像は`ws-fe.amazon-adsystem.com`が使えなくなって、代わりのURLでも一部の商品でしか出ず、ふつうのリンクとほとんど変わらなかったため。PA-APIは使っていなかった。
- AmazonのURLは、ほかのURLと同じふつうのリンクになる。

### はてなの検索の記法（削除）

- `[search:keyword:…]`、`[search:question:…]`、`[search:asin:…]`、`[search:web:…]`と、別名の`[search:k:…]`、`[search:q:…]`は、はてなの検索（`search.hatena.ne.jp`）へのリンクを作る記法だったが、はてなの検索サービスが終わり、どれもはてなのトップページへ転送されるだけだったので、4.09で削除した。`search:asin`（はてなASIN検索）は、Amazonの記法とは関係ない。

### はてな・Googleなどの記法（削除）

4.22で次の記法を削除した。使っていた記事では、記法が文字のまま出る。

- はてなダイアリーの記法：`[jan:…]`（`[ean:…]`）、`[hatena:f:…]`、`[graph:id:…]`（`Tag_hatena.pm`）、`[keyword:…]`、`[hatena:id:…]`、`[hatena:d:…]`。はてな式の引用`>http://～>`～`<<`（`>>[URL]`と同じ）、見出しの時刻記法（`*1234567890*見出し`の日時を見出しの後に出す処理。`*名前*`で見出しのIDを決める機能は残る）。はてなダイアリーのサービスは終わっていて、このCMSははてなダイアリーではないため
- 検索結果や事典へリンクするだけの記法：`[google:…]`（`google:image`、`google:video`、`google:news`、`google:transit`と、別名の`g`、`gi`、`gv`、`gn`、`tr`）、`[wikipedia:…]`（`w`、`wiki`）、`[uc:…]`（アンサイクロペディア）、`[ei:…]`（英辞郎）、`[jman:…]`（`man`）。ふつうはリンク先を確かめてからリンクを貼るもので、確かめずに作ったリンクは、存在しないページや思わぬ検索結果になるため。記事作成画面の入力補助の「検索」「Wikipedia」も削除した
- 動かない記法：`[mtex:…]`（mimeTeX。`mimetex.cgi`が無い）、`[icon:…]`（アイコンの画像が無い）、`[popup:…]`（`popup`のモジュールが無い）、`[theme:…]`（`?_theme=`を受け取る処理が無い）、`[cpan:…]`（`search.cpan.org`は終わっている）、`[footer:…]`（存在しないCSSのプロパティを使っていた）、`[qr:…]`（外部のAPIに頼っていた）
- そのほか：`[twitter:…]`（`tw`）、2つの引数を取る`[niconico:動画ID:文字]`。1つの引数の`[niconico:動画ID]`は残る
- ユーザー定義タグの見本（`info/default_usertag.txt`）と、記法タグの一覧の使用例も、はてなとGoogleの例を差し替えた

### TeX（削除）

4.22でTeX（数式）のサポートをやめ、次のものを削除した。

- 記法タグ：`[math:…]`（`[[math:…]]`）、`[mathd:…]`、`[mref:…]`、`[mrefa:…]`、別名の`[tex:…]`。使っていた記事では、記法が文字のまま出る
- Markdownの` ```math `のブロック（`qiita_math`）。普通のコードブロック（`<pre><code class="language-math">`）になる
- 標準記法のTeXモード（`[*tex]`、`[*tex-off]`、記事ごとの設定の`tex_mode`）。TeXモードの中の`$…$`、`$$…$$`、`\ref{…}`、`\[`～`\]`、`\begin{…}`～`\end{…}`は、数式として扱われなくなる（`{…}`はほかの標準記法と同じくmini verbatimとして処理されるので、`\ref{eq}`は`\refeq`と出る）。標準記法の` ```math `も、普通のコードブロックになる
- 数式があるページでMathJax（jsDelivr）を読み込む処理（`pub/assets/js/adiary.js`）と、数式用のCSS（`pub/assets/theme/base.css`の`div.math`、`span.MathJax`）
- 記事作成画面の入力補助の「数式」「数式（文中）」
- 記事のHTMLは保存してあるので、作り直すまでは数式のHTML（`<div class="math">`など）が残る。MathJaxを読み込まないので、TeXの文字列のまま出る

### 標準記法（削除）

4.22で、記事の記法をMarkdownとHTMLだけにした。

- 標準記法のパーサー（「標準（改行処理）」`default`、「１行＝１段落」`default_p1`、「空行で段落処理」`default_p2`と、選べなかった`default_p2_br`、`default_no_br`）を削除した。使われていなかったHTMLの`simple_p2`、`simple_p3`も削除した。`simple_p`はWordPressの取り込みが使うので残す
- `lib/Satsuki/TextParser/Satsuki.pm`から、標準記法の処理（ブロック、見出し、段落、リスト、表、mini verbatim、記事ごとの設定`::名前=値`、自由変数の定義`:::名前=値`、マクロ）を削除した。残したのは、さつき記法のタグ（`[image:…]`など）、脚注（`((…))`）、目次（`<toc>`）の処理で、Markdownの記事が使う。マクロの定義（`*名前`）は、ユーザー定義タグに残っていても読み飛ばす
- Markdownがタグに使うパーサーの組み立ては、`skel/_parser/default.html`から`skel/_sub/satsuki_tags_parser.html`に移した。記事の記法としては選べない
- 基本設定の「Markdownで入力する」を削除した。既定の記法は、編集画面の設定の「標準の入力方法」で選ぶ
- 標準記法で書いた記事は、作り直さない（保存してあるHTMLのまま出る）。作り直すと「Load parser failed」になり、前のHTMLのまま残る。編集画面では、選べない記法であることを知らせる。MarkdownかHTMLを選んで書き直す
- adiary形式の取り込みで、記事の記法が選べないもの（標準記法など）や空のときは、HTML（改行処理、`simple_br`）で取り込む
- はてな形式の取り込み（はてな記法を標準記法に変える）を削除した。adiary形式の取り込みは残す（処理は同じ`ImportHatena.pm`）。はてな形式のデータを渡すと「adiary形式のデータではありません」と出る
- 記事作成画面の入力補助の、標準記法用の定義を削除した

公開フォルダと非公開のフォルダ

- 公開するのは`pub/`だけ。4.10までルートにあった`js/`、`pub-dist/`、`theme/`は、4.11で`pub/assets/js/`、`pub/assets/dist/`、`pub/assets/theme/`に移した。`adiary::SetDefaultValue`の`script_dir`、`pubdist_dir`、`theme_dir`がこの場所を指す
- `pub/`のうち、`attachments/`のほかは作り直せる。テーマの色の調整の値は、ブログの設定の`theme_custom:テンプレート/テーマ`にテーマごとに保存し（`save_theme_custom_values`）、`pub/custom/theme.css`はそこから今のテーマの分だけを作る（`write_theme_custom_css`）。ブログの設定の`theme_custom`は、色の調整を使っているかどうか（1か空）
- 4.21で`pub/css/`（テーマの色の調整）、`pub/css.d/`、`pub/js/`、`pub/dynamic.css`を、今の場所とブログの設定に移した。`pub/assets/`の`js/`、`theme/`と名前が似ていて紛らわしかったため
- `__cache/`、`data/`、`info/`、`lib/`、`plugin/`、`skel/`、`skel.local/`、`docs/`、`t/`は非公開。ドットで始まるもの（`pub/`と、Apacheでの`.well-known/`を除く）と、`lyndbaum.user.cgi`などの設定ファイルも同じ。Apacheでは根元の`.htaccess`のRewriteRuleで拒否する（見本は`docs/config-example/.htaccess.sample`。mod_rewriteが必要）。nginxでは`location`で拒否する（`docs/config-example/nginx.conf`）
- コンテンツのキー（記事のURLの名前）の先頭の階層には、ルートにあるファイルやフォルダの名前は使えない（`check_link_key_path`。ルートを実際に一覧して調べる）。4.11で`js`、`pub-dist`、`theme`が使えるようになった
