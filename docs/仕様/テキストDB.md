# テキストDB

既定のDB（`lib/Satsuki/DB/text.pm`、`text_2.pm`、`text_3.pm`）。外部のライブラリやDBサーバーを使わず、テーブルの行をファイルで持つ。

## 概要

- `Satsuki::Base`の`setup_main`で`loadpm('DB_text', 'data/db/')`として使う。`lib/Satsuki/DB_text.pm`は、`Satsuki::DB::text`を作って返すだけ。
- 3つのファイルは同じパッケージ（`Satsuki::DB::text`）で、`Satsuki::AutoLoader`で必要になったときに読む。

| ファイル    | 中身                                                                   |
| ----------- | ---------------------------------------------------------------------- |
| `text.pm`   | indexと行の読み込み、検索（`select`）、並べ替え                         |
| `text_2.pm` | 挿入、更新、削除、集計、UNIQUEの確認、トランザクション、indexの保存 |
| `text_3.pm` | テーブルとカラムの作成、削除、名前の変更、indexの作り直し             |

- `select_match`などの短縮形は`lib/Satsuki/DB/share.pm`に、`create_table_wrapper`は`lib/Satsuki/DB/share_3.pm`にある。
- DBはテキストDBだけ。MySQLとPostgreSQLのドライバーはv4.18で外した（理由は`SQLiteに対応しない理由.md`）。
- 共通の約束
  - 空文字とNULLを区別しない。どちらも空として扱う。
  - テーブル名とカラム名は`\w`（英数字と`_`）だけ。それ以外の文字は取り除く。テーブル名は数字で始められない。
  - `pkey`はどのテーブルにも必ずある主キー（後の「pkeyとファイル名」）。

## ファイルの置き方

`data/db/テーブル名/`がテーブルで、中に次のファイルを置く。

| ファイル             | 内容                                                         |
| -------------------- | ------------------------------------------------------------ |
| `#index.dat`         | index。シリアル値、カラムの定義、indexにするカラムの値の一覧 |
| `#index.backup.dat`  | indexのバックアップ                                          |
| `pkeyの数字.dat`     | 1行分のデータ（例：`00001.dat`）                             |

- `#index.backup.dat`は、`#index.dat`と同じ書式で、カラムの定義だけを持つ（行の一覧は空）。テーブルやカラムを作る、消すときに書き直す。`#index.dat`が無いか空のときに、indexを作り直す元にする（後の「indexの作り直し」）。
- `#index.dat`が無くても`#index.backup.dat`があれば、テーブルはあるものとして扱う（`find_table`）。

## indexファイルの書式

`#index.dat`はテキストファイルで、1〜12行目が見出し、13行目からが行の一覧。値はTABで区切る。

| 行  | 内容                                                                                   |
| --- | -------------------------------------------------------------------------------------- |
| 1   | 書式の版。今は`5`                                                                      |
| 2   | ランダム値（`R`+時刻+乱数）。保存のたびに変わり、キャッシュが古いかどうかの判定に使う |
| 3   | シリアル値（後の「シリアル値」）                                                        |
| 4   | すべてのカラム名                                                                        |
| 5   | `int`のカラム名                                                                          |
| 6   | `float`のカラム名                                                                        |
| 7   | `flag`のカラム名                                                                         |
| 8   | 文字列（`text`、`ltext`）のカラム名                                                      |
| 9   | UNIQUEのカラム名                                                                        |
| 10  | NOT NULLのカラム名                                                                      |
| 11  | 既定値。4行目のカラムの順に、値をTABで並べる（既定値の無いカラムは空）                 |
| 12  | indexにするカラム名。先頭は必ず`pkey`                                                   |

- 4〜10行目のカラム名は、名前の順に並べる。12行目は`pkey`の後を名前の順に並べる。
- 13行目からは1行が1レコードで、12行目のカラムの値をその順にTABで並べる。`pkey`の昇順に並べる。
- 値の中のTABと改行は、indexに書くときに空白1つにする。そのため、indexのカラムでの検索では、TABと改行は空白として比べる。行ファイルの値はそのまま残る。
- 古い版も読める。版3以前は、2行目が無く（代わりに使わない値が入っている）、ファイルの更新時刻をランダム値の代わりにする。6、8、9、10行目も無く、文字列のカラムは「intでもflagでもないカラム」、UNIQUEとNOT NULLは`pkey`だけとする。版4以前は11行目（既定値）が無い。保存すると版5で書き直す。

## 行ファイルの書式

`pkeyの数字.dat`は、1行の全カラムを`key=value`の形で並べたもの（`fwrite_hash`、`parse_hash`）。

```
pkey=1
title=題名
*_text=<<__END_BLK_DATA
改行を含む値は
このようにブロックで書く
__END_BLK_DATA
```

- 改行を含む値は`*key=<<__END_BLK_DATA`から`__END_BLK_DATA`の行までに書く。値の中に`__END_BLK_DATA`だけの行があるときは、後ろに空白を足して書く。
- 値が空のカラムは書かない（読むと空になる）。
- `*`で始まるキーは書かない。読み込んだ行には、読み込み済みの印として`*`を付けて持っている。
- 行の順番には意味がない。

## 型と制約

| 型      | 保存するときの値                                       |
| ------- | ------------------------------------------------------ |
| `int`   | `int()`で整数にする                                    |
| `float` | `+0`で数値にする                                       |
| `flag`  | 真なら`1`、偽なら`0`                                   |
| `text`  | そのまま                                               |
| `ltext` | そのまま（テキストDBでは`text`と区別しない）           |

- 空の値は、どの型でも空のまま保存する（`0`にはしない）。
- テーブルに無いカラムを渡すとエラーになる（`check_column_type`）。
- 検索や並べ替えでは、文字列のカラムは文字列として、それ以外は数値として比べる。
- 制約
  - NOT NULL：値が無いときと空文字のときを拒む（`0`は通す）。挿入では、NOT NULLのカラムをすべて確かめる（`pkey`は除く）。更新では、渡したカラムだけ確かめる。
  - UNIQUE：同じ値の行が既にあればエラーになる。空の値は重複とみなさない。`pkey`もUNIQUE。
  - 既定値：挿入で渡さなかったカラムにだけ入れる。
  - 外部キー（`ref`）：テキストDBでは使わない。
- indexにするカラム
  - 定義で`index`か`index_tdb`を付けたカラムと、UNIQUEのカラム。`pkey`は必ずindexになる。
  - indexにしたカラムは`#index.dat`だけで検索できる。index外のカラムで検索すると、行ファイルを読むことになる（後の「検索」）。本文のような大きいカラムをindexにすると、indexが大きくなって遅くなる。
  - 定義のキーと、テーブルごとの定義は`テーブル.md`を参照。

## pkeyとファイル名

- `pkey`は行の番号で、1から順に振る整数。どのテーブルにも必ずある。
- 行のファイル名は`sprintf("%05d", pkey)`で作る（`$FileNameFormat`）。5桁は**最小の桁数で、上限ではない**。`99999`の次は`100000.dat`になる。
  - 読み込み、書き込み、削除は、どれも`pkey`から同じ書式でファイル名を作るので、桁数が変わっても同じファイルを指す。
  - indexを作り直すときは`/^\d+\.dat$/`に合うファイルを拾うので、6桁以上のファイルも対象になる。
  - 行の並び順は`pkey`の数値で比べる。ファイル名の文字列の順には頼っていない。
- 行が10万を超えても、ファイル名が6桁になるだけでそのまま動く。

## シリアル値

- `#index.dat`の3行目は、今までに振った`pkey`の最大値（シリアル値）。
- `pkey`の振り方は2つある。
  - `insert`で`pkey`を渡さないとき：indexを編集用に読んだ後、シリアル値+1を振る。
  - `generate_pkey`：行を作る前に`pkey`だけ先に取る（記事の保存で使う）。取った`pkey`は、`insert`に渡して使う。
- `generate_pkey`は、indexにロックをかけたまま、3行目を同じ長さで上書きして次の値を取る。桁が増える書き換えはできない。
- そのため、indexを保存する（`save_index`）ときは、シリアル値の頭に`00000`を付けて書く（例：`0000099999`）。上書きでは、この0の分まで桁を増やせる。
- indexを保存し直さないまま0の分を使い切ると、`generate_pkey`は`0`を返して失敗する（データは壊さない）。次にindexを保存したときに、また`00000`が付く。
- `save_index`のシリアル値の書き方を変えるときは、`generate_pkey`も合わせて直す。
- `insert`に`pkey`を渡したときは、その値をそのまま使う。シリアル値より大きければ、シリアル値をその値にして、indexと一緒に保存する。小さければシリアル値は変えない。
  - `pkey`を渡して足すところ
    - 記事の新規作成：`generate_pkey`で取った値を渡す。ファイルのシリアル値は`generate_pkey`で進めてあるので、ずれない。
    - ゴミ箱への移動と、ゴミ箱から戻すとき：元の記事とコメントの`pkey`を渡す。
    - インポートで「記事番号（pkey）を保存する」を選んだとき：記事とコメントの元の`pkey`を渡す（`save_pkey`）。

## 検索（select）

`$DB->select($table, \%h)`は、条件に合う行をハッシュの配列で返す。リストの文脈で呼ぶと`($rows, 件数)`を返す（件数は`limit`と`offset`をかける前の数）。

| キー            | 意味                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------ |
| `match`         | `{カラム=>値}`。値が等しい。値を配列にすると、どれかに等しい（IN）                       |
| `not_match`     | `{カラム=>値}`。値が等しくない。配列なら、どれにも等しくない                               |
| `min`、`max`    | `{カラム=>値}`。値以上、値以下                                                             |
| `gt`、`lt`      | `{カラム=>値}`。値より大きい、値より小さい                                                 |
| `flag`          | `{カラム=>0か1}`。値が等しい                                                               |
| `is_null`       | `[カラム]`。値が空                                                                         |
| `not_null`      | `[カラム]`。値が空でない                                                                   |
| `search_words`  | `[語]`。どの語も、後の3つのどれかのカラムに合う                                           |
| `search_not`    | `[語]`。どの語も、後の3つのどのカラムにも合わない                                         |
| `search_cols`   | `[カラム]`。語を含む（部分一致。大文字と小文字を区別しない）                               |
| `search_match`  | `[カラム]`。値の全体が語に合う（大文字と小文字を区別しない）                               |
| `search_equal`  | `[カラム]`。値が語と等しい（大文字と小文字を区別する）                                     |
| `sort`          | 並べ替えるカラム（1つか配列）。カラム名の頭に`-`を付けると降順                            |
| `sort_rev`      | `sort`と同じ順の配列で、真のところを降順にする                                             |
| `limit`、`offset` | 返す行の数と、飛ばす行の数                                                               |
| `cols`          | 返すカラム（1つか配列）。省くと全カラム                                                    |
| `NoError`       | indexが読めなくてもエラーにしない                                                          |

- 条件はすべてANDでつなぐ。
- 数値のカラムに数でない値を渡すと、エラーになって空の配列を返す。テーブルに無いカラムを指定したときも同じ。
- `match`と`not_match`で、値が空のときは空の行と比べる（`is_null`、`not_null`と同じ）。
- 返す行は、中で持っている行のコピー。書き換えても中の行は変わらない。

### 行ファイルを読む段取り

- 条件、並べ替え、返すカラムがすべてindexのカラムなら、`#index.dat`だけで済み、行ファイルは読まない。
- index外のカラムを条件に使うと、テーブルの全行のファイルを読む（`load_allrow`）。読んだ行はキャッシュに残る（後の「キャッシュ」）。
  - ただし、`limit`と`sort`があり、件数を求めず、並べ替えがindexのカラムだけで済むときは、先に並べてから1行ずつ読んで確かめ、`limit`+`offset`に届いたところで止める。
- index外のカラムで並べ替えるときは、条件に合った行のファイルを読んでから並べる。
- index外のカラムを返すときは、`limit`と`offset`で絞った後の行のファイルだけを読む。

### 短縮形と集計

| 関数                                        | 内容                                                                 |
| ------------------------------------------- | -------------------------------------------------------------------- |
| `select_match($table, カラム, 値, ...)`     | `match`の短縮形。`-カラム`は`not_match`。`*limit`、`*cols`、`*sort`、`*NoError`も渡せる |
| `select_match_limit1`                       | `select_match`の最初の1行                                            |
| `select_match_pkey1`                        | `select_match`の最初の1行の`pkey`                                    |
| `select_by_group($table, \%h)`              | `group_by`のカラムでまとめ、`sum_cols`、`max_cols`、`min_cols`を集計する |

- `select_by_group`は、`select`と同じ条件が使える。結果の行は、`group_by`のカラム、`_count`（行の数）、`カラム_sum`、`カラム_max`、`カラム_min`を持つ。`sort`で結果を並べ替える（`limit`と`offset`は使えない）。

## 挿入、更新、削除

| 関数                                          | 戻り値                         |
| --------------------------------------------- | ------------------------------ |
| `insert($table, \%h)`                         | 振った`pkey`。失敗したら`0`    |
| `update_match($table, \%h, カラム, 値, ...)`  | 更新した行の数。失敗したら`0`  |
| `delete_match($table, カラム, 値, ...)`       | 削除した行の数                 |

- `update_match`と`delete_match`の条件は、カラムと値を並べて渡す（ハッシュ1つでもよい）。条件はANDでつなぐ。カラム名の頭に`-`を付けると「等しくない」、値を配列にすると「どれかに等しい」。条件を渡さないと全行が対象になる。
- 条件にindex外のカラムを使うと、テーブルの全行のファイルを読む。
- `update_match`では、`\%h`のキーを`*カラム`にすると、値を式として計算する（例：`'*coms' => 'coms+1'`）。式の中のカラム名は、その行の値になる。関数の呼び出しはできない。`pkey`は書き換えられない。
- 書き込みの順番
  - 挿入と更新は、行ファイルを書いてからindexを保存する。
  - 削除は、行ファイルを消してからindexを保存する。
  - indexの保存に失敗すると、行ファイルだけが変わった状態になることがある。indexを作り直せば、行ファイルに合わせられる。

## ロック

- 挿入、更新、削除、カラムの操作は、`#index.dat`を編集用に開いて書き込みのロックをかけ（`fedit_readlines`）、indexを置き換えるまで持つ（`fedit_replace`）。そのため、同じテーブルへの書き込みは1つずつ行う。
- indexは一時ファイルに書き終えてから`rename`で置き換える（`fwrite_atomic`）。書き込みに失敗したり途中で落ちたりしても、前のindexが残る。
- 行ファイルも同じ方法で書く（`write_rowfile`が`fwrite_hash`に`atomic`を付ける）。書けなかったときは、行の前の中身が残る。`update_match`と`commit`はindexを保存せずに失敗を返す（`commit`は`1`）。
- 置き換えるとファイルの実体が変わるので、ロックを取った後に、開いたものが今の`#index.dat`かを確かめ、違えば開き直す（`file_replaced`）。`generate_pkey`も同じ。
- 途中でエラーになったときは、indexを書かずにロックを解き（`edit_index_exit`）、そのテーブルのキャッシュを消す。
- `generate_pkey`は、`#index.dat`に書き込みのロックをかけて3行目だけを上書きする。
- 読み込み（`fread_lines`）は読み込みのロックをかけるので、indexや行ファイルを書いている最中のものは読まない。

## トランザクション

`begin`、`commit`、`rollback`。たくさんの行をまとめて書くのを速くするためのもので、`insert`、`update_match`、`delete_match`だけが対象。

- `begin`の後、テーブルを初めて書くときに、`#index.backup.dat`にロックをかける。待たずにロックを取りにいき、ほかのトランザクションが使っていれば失敗する（待つとデッドロックの恐れがあるため）。
  - `#index.dat`には読み込みのロックをかける（ほかの読み込みは止めない）。
- トランザクションの間は、行ファイルの書き込みと削除を記録するだけで、ファイルは変えない。indexも保存しない。
- トランザクションの間に`generate_pkey`を呼ぶと、ファイルを書かずに、メモリの上でシリアル値+1を振る。
- `commit`で、行ごとに最後の操作（書き込みか削除か）だけを行い、`#index.dat`を書き込みのロックに切り替えて保存し、ロックを解く。成功すると`0`を返す。
- 途中でエラーがあったときは、`commit`は`rollback`になり、`-1`を返す。`rollback`は、記録を捨ててロックを解き、キャッシュを消す。
- 2つ目の`begin`は警告を出して無視する（入れ子にはできない）。

## キャッシュ

- indexを読んだ結果は、DBのオブジェクトと、パッケージの変数（`%IndexCache`）の2か所に持つ。
  - オブジェクトのキャッシュがあれば、ファイルを見ずにそれを使う。
  - `%IndexCache`はプロセスが続く間残る（`lyndbaum.fcgi`で常駐しているとき、次のリクエストでも使う）。indexを読み直したとき、2行目のランダム値が同じなら、行の一覧を作り直さずにキャッシュを使う。
- indexのファイルと行ファイルは、`fread_lines_cached`と`fread_hash_cached`で読み、ファイルの更新時刻（秒より細かい値）と大きさが同じならキャッシュを使う。
- 全行のファイルを読んだら（`load_allrow`）、そのことも覚えておき、次からは読み直さない。
- UNIQUEのカラムの値の一覧もキャッシュし、挿入、更新、削除のたびに足し引きする。
- 書き込みに失敗したとき、テーブルを消したときや名前を変えたときは、そのテーブルのキャッシュを消す（`clear_cache`）。

## テーブルとカラムの操作

| 関数                                | 内容                                                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `create_table($table, \@cols)`      | ディレクトリと`#index.dat`、`#index.backup.dat`を作る。テーブルが既にあればエラー                      |
| `create_table_wrapper($table, \%h)` | 型ごとのカラム名の一覧から`create_table`を呼ぶ（`テーブル.md`）                                        |
| `drop_table($table)`                | ディレクトリの中のファイルとディレクトリを消す。成功したら`0`                                          |
| `rename_table($table, $new)`        | ディレクトリの名前を変える。成功したら`0`。新しい名前のテーブルが既にあれば失敗                        |
| `add_column($table, \%col)`         | カラムを足す。既定値があれば、既存の行のファイルにも書く。無ければ行ファイルは変えない（どの行も空） |
| `drop_column($table, $col)`         | カラムを消す。そのカラムに値がある行のファイルを、カラムを除いて書き直す                               |
| `add_index($table, $col)`           | カラムをindexにする。全行のファイルを読んで、そのカラムの値をindexに書く。既にindexなら何もしない      |
| `index_rebuild($table)`             | indexを作り直す（次の節）                                                                              |

- カラムの定義（`create_table`、`add_column`に渡すハッシュ）：`name`、`type`（`int`、`float`、`flag`、`text`、`ltext`）、`index`、`index_tdb`、`unique`、`not_null`、`default`。どちらも同じキーを使う。
- カラムを足す、消す、indexにするときは、`#index.dat`と`#index.backup.dat`の両方を書き直す。
- 既にあるブログにカラムを足すときの手順は`アップデート処理.md`を参照。

### indexの作り直し

- `#index.dat`が無いか空で、テーブルのディレクトリがあるとき、indexを読もうとすると（`load_index`、`generate_pkey`）作り直す。
- `#index.backup.dat`からカラムの定義を読み、`/^\d+\.dat$/`に合う行ファイルをすべて読んで、indexを書く。シリアル値は、行ファイルの`pkey`の最大値にする（次に振るのはその+1）。
- `#index.backup.dat`も無いか空のときは作り直せない。
