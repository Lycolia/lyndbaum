# アップデート処理

新しい版にしたときに、データやブログごとに作ったファイルを新しい版に合わせる処理。システム管理者が`?system/update`の「アップデート処理を行う」で行う。

## いつ要るか

- システムの情報（`data/system_config.dat`）の`VERSION`が、プログラムの`$DATA_VERSION`（`lib/SatsukiApp/adiary.pm`）より古いと、アップデート処理が要る（`require_update`）
- このとき、ダッシュボードとログインの後に案内を出し、`?system/update`のボタンを押せるようにする
- 処理を行うと、`VERSION`を`$DATA_VERSION`にする。同じ版でもう一度は行わない
- `VERSION`が4.31より古いデータからはアップデートできない。画面で知らせてボタンを押せなくし、送られても何も変更せずに断る（`update_unsupported`）。先に4.32の版でアップデート処理を行う
- 4.31より古いデータに新しい版を置くと、管理者でなかったユーザーも管理者として動く。`_users`の`isadmin`を見なくなったため。先に4.32の版でアップデート処理を行ってから置く

## 何をするか

版ごとの処理は、`lib/SatsukiApp/adiary_6.pm`の`@update_versions`に書く。今の`VERSION`より新しい版の処理を、古い順に行う（`system_update`）。

| 項目           | 内容                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| `ver`          | 版                                                                                                           |
| `func`         | その版で行う処理（メソッドの名前）。ブログが無ければ行わない                                                 |
| `system`       | 真なら、ブログが無くても`func`を行う                                                                         |
| `plugin`       | すべてのプラグインを入れ直す。デザインも作り直す（下の「プラグインの入れ直し」）                             |
| `rebuild`      | すべての記事を作り直す                                                                                       |
| `rebuild_cond` | 本文（原文）が、どれかの正規表現に当たる記事だけを作り直す                                                   |
| `theme`        | テーマのカスタムCSS（配色を変えたブログ用に作ったCSS）を作り直す（`remake_theme_custom_css`）                |
| `info`         | ブログの付加情報（RSSなど）を作り直す（`blog_info_rebuild`）                                                 |

- 新しい版の処理が複数あるときは、`func`を版ごとに行い、`plugin`などの項目は1つでも真なら最後に1回だけ行う
- 順番は、`func`（版ごと）、記事の作り直し（`rebuild`、無ければ`rebuild_cond`）、プラグインの入れ直し、カスタムCSSの作り直し、付加情報の作り直し
- 記事を作り直すと、記事やコメントの状態が変わったときのイベントも呼び、付加情報もそこで作り直すので、`info`は行わない

### 使わなくなった列の削除

4.33より古い版からのときは、マルチサイトと複数ユーザーの残りの列を消す（`sys_update_433`、`drop_column`）。消した値は元に戻せないので、先に`data/db/`のバックアップを取る。

- `_users`の`isadmin`、`disable`を消す
- `art`、`trash`の`name`、`id`、`ip`、`host`、`agent`と、`trash`の`deleted_id`を消す
- 記事情報モジュールの「投稿者の表示」の設定（`p:dea_art-info:author`）を消す
- 処理を行うまでは、列が残っていても読まないので、新しい版のまま動く
- 消せない列があれば画面で知らせ、版は上げる。残った列は読まないので、動きは変わらない

### プラグインの入れ直し

`plugin`は、すべてのプラグインを外してから入れ直す（`reinstall_plugins`）。デザインモジュールも入れ直し、デザインを保存し直す（`reinstall_design_plugins`、`save_design`）。

- デザインの保存で、ブログ用のスケルトン（`data/blog/skel/`と、独自のスケルトンを持つテーマごとの`data/blog/skel_theme/`）を作り直す（[スケルトン](スケルトン.md)）
- そのため、テーマの雛形（`_skel/`）を変えたときも、`theme`ではなく`plugin`で作り直す

## どの変更に何が要るか

| 変更したもの                                                                 | 要る項目                                  |
| ---------------------------------------------------------------------------- | ----------------------------------------- |
| プラグイン（`plugin/`）の処理、設定、モジュールのHTML                        | `plugin`                                  |
| テーマの雛形（`pub/assets/theme/テーマ名/_skel/`）                           | `plugin`                                  |
| 雛形（`skel/`）のうち、モジュールを置く場所のあるもの（`_article`、`_main`、`_sidebar`、`_header`） | `plugin`                                  |
| 記法の変換（`lib/Satsuki/TextParser/`）や、記事のHTMLの出し方                | `rebuild`、または当たる記事だけ`rebuild_cond` |
| テーマのCSSのうち、カスタムCSSの元になる部分（配色）                         | `theme`                                   |
| RSSなど付加情報の出し方                                                      | `info`                                    |
| データの持ち方（テーブル、設定のキーなど）                                   | `func`（`system`も要るか確かめる）        |
| そのほかのスケルトン（`skel/`の`_sub/`、管理画面など）、CSS、JavaScript、Perlの処理 | 要らない（置けば反映する）                |

- `$DATA_VERSION`を上げて、`@update_versions`に項目を足す。`$DATA_VERSION`を上げないと、アップデート処理は行われない
- 一度アップデート処理を行った環境（開発環境など）で、同じ版の項目を足したり変えたりしたときは、もう一度は行われない。`?system/update`の「プラグイン再インストール」「全記事の再構築」などのボタンで、手で行う

## アップデート処理の後に、ブラウザーで行うこと

サーバーではできないことは、アップデート処理の後に`?system/update`に戻り、管理者のブラウザーで続けて行う（`system/_action/update`が`&video_thumbnail=1`を付けて戻す）。

- 動画のサムネイルの作成（[動画のサムネイル](動画のサムネイル.md)）
