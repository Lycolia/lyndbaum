# スケルトン

画面のHTMLは、スケルトン（テンプレート）から作る。同じ名前のスケルトン（`_article`など）が複数の場所にあり、どれを使うかは場所の「レベル」で決まる。

## 探す順番

画面を出すときは、登録した場所をレベルの高い順に探し、最初に見つかったスケルトンを使う（`lib/Satsuki/Base.pm`の`regist_skeleton`、`check_skeleton`）。レベルの値は`lib/SatsukiApp/adiary.pm`の`theme_skeleton_level`など。

| レベル | 場所                               | 中身                                                                                 | 手で直すか |
| ------ | ---------------------------------- | ------------------------------------------------------------------------------------ | ---------- |
| 21     | `data/blog/skel_theme/テーマ名/`   | デザインの保存で作る。独自のスケルトンを持つテーマ用。今のテーマのものだけ登録する   | 直さない   |
| 20     | `data/blog/skel/`                  | デザインの保存で作る。独自のスケルトンを持たないテーマ用                             | 直さない   |
| 10     | `pub/assets/theme/テーマ名/_skel/` | テーマが持つ雛形（lyndbaumなど）。今のテーマのものだけ登録する                       | 直す       |
| 2      | `skel.local/`                      | サイトごとに差し替えたいとき用（`Satsuki::Base`の`setup_main`で登録）                            | 直す       |
| 0      | `skel/`                            | 標準の雛形（`Satsuki::Base`の`setup_main`で登録）                                                | 直す       |

- レベル20と21は、プラグインを全部止めているとき（`stop_all_plugins`）は登録しない。デザインを一度も保存していないときは、ファイルが無いので使われない。どちらの場合も、テーマの雛形か標準の雛形がそのまま使われる
- 管理画面（`system_mode`）では、テーマを使わない。レベル10と21を外し、テーマのCSSも読まない。管理画面のフレーム（`_frame_admin`）は`admin.css`で、公開画面のフレームを使うデザイン編集、テーマ選択、デザインの初期化（`special_system_mode`）は`pub/assets/js/design.css`で表示する
- スマホ用の差し替えは無い。テーマはどれもレスポンシブで、狭い画面にはテーマのCSS（`@media`）で合わせる

## デザインの保存で作るもの

デザインを保存すると（`lib/SatsukiApp/adiary_4.pm`の`save_design`）、雛形にデザインモジュールのHTMLを差し込んで、ブログ用のスケルトンを作る（`generate_design_skeleton`）。

- 雛形は、レベル10以下（テーマの雛形、`skel.local/`、`skel/`）から探す（`parse_original_skeleton`）。作ったもの（レベル20、21）は使わない
- `data/blog/skel/`は、標準の雛形（テーマの雛形を除く）から作る
- `data/blog/skel_theme/テーマ名/`は、独自のスケルトンを持つテーマ（`_skel/`のあるテーマ）ごとに、そのテーマの雛形から作る。テーマを切り替えても作り直さずに済むように、今のテーマ以外の分も作る
- 作るのは`_sidebar`、`_header`、`_article`、`_main`など、モジュールを置く場所のあるスケルトンだけ
- プラグインを入れ直したとき（`reinstall_design_plugins`。アップデート処理の`plugin`も）にも作り直す

### 雛形の区切り

雛形の中には、`<@>$名前$`と`<@>$名前:END$`の区切りがある。区切りの中身を取り出し、モジュールを置く場所に、置いたモジュールのHTMLを並べる。

`_article`の例：

| 区切り                                 | 中身                                                         |
| -------------------------------------- | ------------------------------------------------------------ |
| `$HEADER$`                             | 記事の前の部分。そのまま使う                                 |
| `$ARTICLE_TOP$`、`$ARTICLE_MIDDLE$`など | 記事の部分。この間に、記事の上、下に置いたモジュールを並べる |
| `$COMMENT_TOP$`                        | コメントの一覧。そのまま使う                                 |
| `$COMMENT_BOTTOM$`                     | コメント欄の後。そのまま使う                                 |

- 区切りの外にある部分は、作るときに捨てる。`_article`の`$COMMENT_TOP:END$`と`$COMMENT_BOTTOM$`の間は、デザインを保存していないとき（雛形がそのまま使われるとき）の既定の中身で、保存すると、置いたモジュール（`dec_comment-form`など）のHTMLに置き換わる

## モジュールのHTML

雛形の既定の中身と同じHTMLを持つデザインモジュールは、HTMLを`skel/_sub/`のスケルトンだけに書く（WordPressの`comment_form()`と同じ考え方）。モジュールと雛形の既定の中身（`skel/`と、テーマの`_skel/`）は、それを呼ぶ1行だけにする。

| スケルトン                    | モジュール                      | 雛形の場所                     | 引数（1つ目はどれもモジュール名）     |
| ----------------------------- | ------------------------------- | ------------------------------ | ------------------------------------- |
| `_sub/header_login.html`      | ログイン（`deh_login`）         | `_header`                      |                                       |
| `_sub/header_title.html`      | タイトル（`deh_title`）         | `_header`                      | 要素のid                              |
| `_sub/side_search.html`       | 検索（`des_searchbox`）         | `_sidebar`                     | 要素のid                              |
| `_sub/side_system_info.html`  | システム情報（`des_system-info`） | `_sidebar`                   |                                       |
| `_sub/page_nav_article.html`  | ページ送り（`dem_page-nav`）    | `_article`の上と下             | 記事                                  |
| `_sub/page_nav_main.html`     | ページ送り（`dem_page-nav`）    | `_main`の上と下                | 記事の一覧、ページの番号、URLの元     |
| `_sub/art_info.html`          | 記事の情報（`dea_art-info`）    | `_article`、`_main`の記事の上  | 記事                                  |
| `_sub/node_list.html`         | 記事リスト、関連記事（`dea_node-list`） | `_article`の記事の下   | 記事                                  |
| `_sub/com_count.html`         | コメント数（`dea_com-count`）   | `_main`の記事の下              | 記事                                  |
| `_sub/comment_form.html`      | コメント欄（`dec_comment-form`） | `_article`のコメントの下      | 記事、記事のURL                       |

- 管理バー（`_sub/admin_bar.html`）はモジュールではなく、`_frame.html`が呼ぶ。ログイン中のメニューはこちらに出し、`_sub/header_login.html`はログアウト中だけ中身を出す（デザインの編集では、ログイン中でも出す）
- 呼び出しは画面を出すときに解決するので、`_sub/`のスケルトンを直せば、デザインを保存し直さなくても反映する
- テーマで見た目を変えたいときは、テーマの`_skel/_sub/`に同じ名前で置く。テーマの雛形は標準の雛形よりレベルが高いので、そちらが使われる
- テンプレートの`local`は呼び出し先から見えない（Perlの`my`になる）ので、記事などは引数で渡す
- Information（`des_information-ja`）は、設定に合わせてHTMLをPerlで組み立てる（`html_generator.pm`）ので、この形にしていない。雛形の既定の中身は、設定をしていないときと同じ「説明文だけ」の形

## 直したものを反映するには

雛形（`skel/`、テーマの`_skel/`）やモジュールのHTML（`plugin/*/module.html`）を直しても、ブログ用に作ったスケルトン（`data/blog/`）は古いまま残る。デザインを保存し直すか、プラグインを入れ直して作り直す。

- アップデート処理でプラグインを入れ直す（`@update_versions`の`plugin`）と、すべてのブログで作り直す
- 雛形のうち、モジュールを置く場所の無いスケルトン（`_frame`など）は、ブログ用に作らないので、直せばすぐに反映する
