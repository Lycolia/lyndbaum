# OGP

記事のページ（コンテンツページと下書きを含む）とトップページの`<head>`に、OGPとTwitter Cardのメタタグ、`canonical`、`meta description`を出す（`Lyndbaum::OGP`、`Lyndbaum::App->page_head`）。検索の結果などのほかのページには出さない。

## 出すもの

| タグ                                                        | 記事                                                       | トップページ                                  |
| ----------------------------------------------------------- | ---------------------------------------------------------- | --------------------------------------------- |
| `link rel="canonical"`、`og:url`                            | 記事のURL                                                  | トップページのURL（2ページ目からは`?page=N`） |
| `og:type`                                                   | `article`                                                  | `website`                                     |
| `og:title`、`twitter:title`                                 | 記事の題名                                                 | ブログの名前                                  |
| `meta description`、`og:description`、`twitter:description` | 記事の説明（本文の先頭64文字）                             | ブログの説明                                  |
| `og:image`、`twitter:image`                                 | 記事の画像（下）。無ければブログの画像                     | ブログの画像                                  |
| `og:site_name`                                              | ブログの名前                                               | ブログの名前                                  |
| `og:locale`                                                 | `ja_JP`                                                    | `ja_JP`                                       |
| `twitter:card`                                              | 記事の画像があれば`summary_large_image`、無ければ`summary` | `summary`                                     |

- URLは絶対URLにする。元は`config.json`の`site_url`。無ければリクエストのホスト名から作る
- 値の無いもの（説明が空、ブログの画像が無いなど）は出さない
- 旧システムとの違い：`og:locale`は空だったので`ja_JP`を入れる。`twitter:url`はXの仕様に無いので出さない

## 記事の画像（アイキャッチ）

次の順に決める（WordPressのアイキャッチ画像に合わせ、決め方の選択は持たない）。

1. 選んだ画像（`articles.eyecatch`。添付ファイルの中のパス「フォルダ/名前」）
2. 本文の最初の画像。サムネイルを元の画像へのリンクで囲んでいれば（`[image:S:…]`）、元の画像（旧システムと同じ）
3. ブログの画像（下）

- 編集の画面の「アイキャッチ画像」の枠で、「アイキャッチ画像を設定」を押すとメディアの窓（`docs/admin.md`の「メディア」）が開く。画像を選んで「アイキャッチ画像に設定」を押すと、その画像にする。本文の下の「ファイル一覧から選択」の窓では選ばない（本文に入れるためのもの）
- 選んだ画像は、押すと選び直せる。「アイキャッチ画像を削除」を押すと選んでいない状態に戻る（2か3になる）
- 選んでいないときも、枠には使う画像と、どれを使うか（本文の最初の画像か、ブログの画像か）を出す
- 旧データで画像（`main_image`）が決まっている記事は、その画像を選んだものとして取り込む
- 検索結果にも、本文の左に小さく出す（作者の判断）。トップの一覧は本文をすべて出すので出さない（出すかどうかはテンプレートで決める。`docs/templates.md`）。添付ファイルの画像だけを出し、外部のサイトの画像は出さない（一覧で外部の大きな画像を読み込まないため）。サムネイル（`.thumbnail/名前.jpg`）があればサムネイルを、無ければ元の画像を縮めて出す。ブログの画像は一覧には出さない
- 旧システムは、OGPの欄が空なら本文の最初の画像、書けばその画像だった（同じ）。以前あった「使わない（ブログの画像を出す）」は、WordPressに合わせてなくした

## ブログの画像

ブログの設定の画面の「ブログの画像」のフォームで入れ替える（`docs/admin.md`の「サイトのアイコンとブログの画像」。`Lyndbaum::BlogImage`）。

- 入れた画像は、手を加えずに`pub/branding/blog-image-時刻.拡張子`に置く。設定の`blog_image`はその名前。入れ替えるとURLが変わるので、OGPを読むサービスに古い画像を使わせない。前の画像は消す
- 消すと、OGPに画像を出さない
- 前は添付ファイルの中のパス（例：`@system/sys-blog_image.png`）を「ファイル一覧から選択」で選んでいた。その書き方の値は、入れていないものとする（入れ直す）
- 旧データの`blog_image`は、取り込むとき（`tools/import-adiary.pl`）に添付ファイルの中から`pub/branding/`へ写す。添付ファイルを先に置いておく（`docs/migrate-from-adiary.md`）
